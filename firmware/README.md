# 接入现有小车 PID

这里是通用 C99 参数接口，不包含 PID 算法、不增加控制环，也没有修改你的固件工程。它绑定一个已有 PID；具体变量和串口驱动需要拿到工程后接入。

1. 把 `pid_link.c` / `pid_link.h` 加入已有工程。
2. 提供三个回调：`read` 读取实际 P/I/D；`apply` 将三个值完整写入现有 PID，确认完成后返回 1；`send` 把一整条回复加入串口发送队列。
3. 用 `pid_link_init(&link, "steering", context, read, apply, send)` 绑定明确的已有控制环。界面会显示这个名称。
4. UART 接收中断只收字节入环形缓冲区。主循环取出字节后调用 `pid_link_feed`。不要在中断中解析、格式化字符串或发送回复。
5. 在现有控制周期的安全边界调用 `pid_link_poll`，在该边界完成参数更新后，再计算下一次 PID。若控制计算在中断中，回调和快照需要按现有工程设计保护，防止三个系数被读到一半。
6. 继续输出 FireWater 波形，例如 `target,actual,error,output\n`；软件选择 `PIDLink（实时调参）`，设置与设备一致的通道顺序。

波形和回复共用一个串口发送队列，保证每条完整的行不会相互交织。输出波形频率应按波特率和实际帧长安排。该参考实现使用 `strtof` / 浮点 `snprintf`，有些嵌入式工具链需要打开浮点格式化支持；实际工程可以换用已有解析和输出函数。

## 协议 v1

ASCII 文本，换行结束，接收可分包。请求 ID 和控制环名称只允许 1–32 个英文字母、数字、下划线或连字符。

```text
电脑：@PID GET a1
板子：@PID STATE a1 0 steering 2 1 0.05

电脑：@PID SET a2 0 steering 1.8 1 0.05
板子：@PID STATE a2 1 steering 1.79999995 1 0.0500000007

拒绝：@PID ERROR a2 STALE
```

SET 中的数字 0 是电脑上次回读的版本。若 IDE 或其他代码改变参数，`poll` 会检测实际值变化并增加版本，拒绝过期 SET，避免静默覆盖。SET 回包只能在实际应用之后发送，回包里的值必须来自真实 PID，而不能照抄输入字符串。

桌面仅接受匹配当前请求的回复；没有收到回包时不确认生效、不重发 SET。重复的同一 SET ID 不会再次应用。P/I/D 在本版界面及参考接口中为 0–10000；还应在 `apply` 回调里按真实 PID 的单位、算法和范围进一步校验。目标值、输出限幅、积分状态与控制周期均不通过此接口改变。

这些修改是运行时参数，重新上电后的默认值由现有固件决定。暂不写 Flash，也不自动修改 C 源码。
